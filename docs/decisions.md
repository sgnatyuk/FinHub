# Решения

Продуктовые и архитектурные решения с причинами. Новые — в конец раздела.

## Продукт

| Решение | Почему |
| --- | --- |
| Учитываем только траты. Доход — когда-нибудь отдельным пакетом `income`, без общей Operation с полем Type | Не плодить ветвления `if type == ...` ради фичи, которой может не быть |
| Сумма траты всегда положительная | Знак не кодирует направление денег; доход не сломает смысл данных |
| У траты ровно одна категория; тегов 0..10 | Суммы по категориям складываются в итог; теги — срезы, пересекаются |
| Категория — «на что» (Транспорт), тег — «зачем/контекст» (`отпуск-2026`). Если X встречается у трат разных категорий — это тег | Чтобы понятия не смешивались |
| Тег: строчные буквы, цифры, дефис, до 32 символов; не может совпадать с именем категории хаба | Защита от путаницы на уровне домена |
| Тег — значение (`type Tag string`), не сущность; таблица `expense_tags` нужна только адаптеру | У тега нет жизненного цикла |
| Категории плоские, без подкатегорий | Хватает на старте |
| Хаб — общий учёт трат (личный, семейный). Входит человек; хаб — это права (членство) | Один аккаунт, несколько хабов |
| Личный хаб «Личное» создаётся при регистрации | Пользователю всегда есть куда писать траты |
| Трата принадлежит одному хабу и имеет автора | «Чей бюджет» и «кто платил» — разные вопросы |
| Категории общие на хаб; новый хаб получает стартовый набор (Продукты, Транспорт, Жильё, Кафе, Здоровье, Прочее) | Семья пользуется одним списком; не начинать с пустого |
| Трата без категории идёт в «Прочее»; «Прочее» нельзя переименовать или удалить | Быстрый ввод в боте |
| Удаление категории переносит её траты в «Прочее» | Ничего не теряется |
| Валюта — настройка хаба (RUB по умолчанию, USD); траты пишутся в валюте хаба; статистика считает валюты раздельно | Одна валюта на бюджет, без конвертации |
| Часовой пояс — настройка хаба (Europe/Moscow по умолчанию), время хранится в UTC | Граница «месяца» в статистике по местному времени |
| Отчёт «мои траты по всем хабам»: по хабам и по категориям (объединяются по имени) | Нужен автору |
| Перенос траты между хабами не делаем | Пока не нужен; можно удалить и записать заново |

## Права

| Действие | Участник | Владелец |
| --- | --- | --- |
| Писать траты, видеть траты и статистику хаба | да | да |
| Править и удалять свои траты | да | да |
| Править и удалять чужие траты | нет | да |
| Создавать категории | да | да |
| Переименовывать и удалять категории | нет | да |
| Добавлять участников, менять валюту и пояс (`/config`) | нет | да |

## Клиенты (план)

- CLI: вход по токену, активный хаб в сессии (`finhub hub use семья`), разово `--hub`.
- Telegram: в личке — хаб по умолчанию; групповой чат привязывается к хабу, трата пишется от имени отправителя.
- Приглашение в хаб — код или ссылка, решим при работе над клиентами.

## Архитектура

- Хранение: PostgreSQL, pgx + ручной SQL, миграции goose, без ORM. Агрегации статистики — в SQL.
- ID — `bigint generated always as identity`, в Go — отдельные типы `user.ID`, `hub.ID`, …
- Хаб не создаёт свои категории сам: `category` импортирует `hub`, обратный импорт дал бы цикл.
  Связку «хаб + стартовые категории» делает вызывающий код.
- Удаление категории с переносом трат — одна транзакция в `category.Repository.Delete`.
