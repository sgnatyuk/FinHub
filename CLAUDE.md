# FinHub

Учебный проект на Go: трекер расходов с общими хабами (семья), категориями, тегами и статистикой.
Цель автора — переучиться с PHP/Laravel на идиоматичный Go, поэтому решения объясняются
с контрастом «как в Laravel → как в Go». Общение на русском.

## Структура

```
cmd/finhub-cli, cmd/finhub-bot   — будущие клиенты, сборка зависимостей вручную в main.go
internal/
  money/     сумма в минимальных единицах (int64) + валюта; RUB, USD
  user/      user.ID
  hub/       хаб, участники (owner/member), валюта и часовой пояс хаба
  category/  категории хаба, стартовый набор, «Прочее» по умолчанию
  expense/   траты (HubID + AuthorID), теги, частичное обновление
  stats/     суммы по категориям, тегам, авторам, по всем хабам пользователя
  postgres/  (следующий шаг) реализации Repository на pgx
```

Архитектура и как добавлять фичи — `docs/architecture.md`. Продуктовые решения и их причины — `docs/decisions.md`. Что сделано и что дальше — `docs/roadmap.md`.
Маршрут по коду для изучения — `docs/code-tour.md`: при изменении кода, который там разобран, обнови и его.

## Конвенции

- Пакеты по фичам, а не по слоям; нет `models/`, `utils/`, `pkg/`.
- Ядро (`internal/*` кроме адаптеров и клиентов) не импортирует БД и клиентов.
- Интерфейсы объявляет потребитель и только с нужными методами (`expense.Hubs`, `expense.Categories`);
  в тестах проверка `var _ expense.Hubs = (*hub.Service)(nil)`.
- Ошибки — значения: sentinel-ошибки пакета, обёртка `fmt.Errorf("...: %w", err)`, проверка `errors.Is`.
- `ctx context.Context` — первый аргумент методов с I/O; зависимости через ctx не передаются.
- Кто действует (`actor user.ID`) и в каком хабе (`hub.ID`) передаётся явно; сервис сам проверяет участие и роль.
- Инварианты сущности проверяются в конструкторе `New`, проверки с данными хранилища — в сервисе.
- Деньги никогда не float.
- Тесты: стандартный `testing`, табличные, рукописные in-memory fakes, без мок-фреймворков.
- Комментарии в коде — на русском.
